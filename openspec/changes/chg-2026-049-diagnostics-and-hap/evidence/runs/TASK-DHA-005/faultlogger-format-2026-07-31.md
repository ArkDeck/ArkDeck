## 1. 为什么现在能 pin

D9 当时只拿到空态输出(`No fault log exist.`),因为设备上没有 fault log。
2026-07-31 的 GJ-5 窗口给 demo 注入了一条 launch 探针,应用**真的崩了一次**,
设备上因此存在一条真实条目 —— 正是 pin「有崩溃时」形态的时机。

## 2. 命令面(实测,`-h` 只列出 `-h`,但 `-l`/`-f`/`-t` 都可用)

```text
hidumper -s 1201 -a "-p Faultlogger -h"     → Usage/Examples;Available Options 只列 -h
hidumper -s 1201 -a "-p Faultlogger -l"     → 条目列表
hidumper -s 1201 -a "-p Faultlogger -f <条目名>"  → 该条目的完整内容(未在 -h 中列出,实测可用)
hidumper -s 1201 -a "-p Faultlogger -t 20250821100000"  → 该时间之后的条目(见 Examples)
```

**列表输出形态**(条目名夹在两行 `******` 之间,每行一条):

```text
-------------------------------[ability]-------------------------------


----------------------------------HiviewService----------------------------------
Fault log list:
******
jscrash-com.example.waterflowdemo-20010057-20260731162134
******
```

条目名 = `<kind>-<bundleName>-<uid>-<yyyyMMddHHmmss>`,**不含 `/`**,与磁盘文件
`/data/log/faultlog/faultlogger/<条目名><毫秒>.log` 对应(实测该文件 108,974 字节,
owner `hiview:system`,mode `-rw-rw-r--`)。这支持把 `crashLogName` 的 pattern 收窄到条目名。

**空态形态**(D9 已 pin,保持不变):`No fault log exist.` + 空的 `Fault log list:` 段。

**对实现的三点约束(由上面的字节形态得出,不是推测)**:

1. **判定字段是 `Reason:` / `Error name:` / `Error message:` / `Stacktrace:`**,不是
   `Reason:Signal:` + `Fault thread info:` —— 后者属 cppcrash。解析器必须按 `kind`
   (条目名前缀 `jscrash` / `cppcrash` / `appfreeze` …)分派,而不是假设只有一种;
2. **条目里自带一段 `HiLog:`**,与 `hilog -x` 的内容重叠 → artifact 的隐私级别应与
   hilog 同级(sensitive),且不要在派生产物里重复这段;
3. **空列表是正常结果**(设备没崩过),必须与失败区分 —— 与 r6 proposal 里
   「空列表是正常结果而 `invalid parameters.` 是失败」一致。

## 4. 为什么这条事实对 CHG-2026-054 也是决定性的

GJ-5 的 crash 判定当前全部以 `hilog.txt` 为源,而**判定信息只在 faultlog 条目里**:
同一次真实崩溃,harness 采到的 887 KB hilog 里 `Reason:` / `Error message:` /
`Stacktrace:` 一个都没有(实测计数为 0)。故 CHG-2026-054 的 fail 路径必须等本任务
落地后才能取得真机证据(见 `chg-2026-054-agent-harness-task-plane/evidence/runs/
TASK-HTP-006/run-r6-fail-path.md`)。

## 5. 边界

- 本轮**只读**:`hidumper` 两条查询 + `ls -l` + `head`。没有删除、没有导出条目文件、
  设备状态未变;
- 记录里给出的内容是**本 agent 自己注入的探针**造成的崩溃(demo 应用),不含第三方数据;
  设备序列号全程 mask;
- **`-f` 未在 `-h` 里列出**:实测可用,但属未文档化选项面,实现时应对「未来版本移除 `-f`」
  留一条明确的失败路径(不要静默降级成空结果)。
