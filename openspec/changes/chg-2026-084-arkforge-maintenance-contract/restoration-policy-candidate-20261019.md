# Original-ramdisk restoration policy candidate — 2026-10-19

This is the unapproved revision-2 candidate for CHG-2026-084. It does not record
hardware acceptance or publish a Runtime. Maintainer review and protected-main
publication remain required before the policy can issue authority.

The candidate changes `flash.restore-boot-loop@1`'s default issuance flag from
disabled to enabled. The Catalog digest is
`88c20a2c364b87ae6e7327edfd1b3bffecaeeff2e67f71dbd6aaa43db74ec195`;
the prior published digest is
`9b184df93d8130d0c7448301844f9afa61137e08f111c77bcaa57261303f319a`.
Its destructive effect, device exclusion, confirmed binding, source/Artifact
requirements, exact original 4 MiB ramdisk plan, independent full-hash readback,
one-use reservation and no-replay behavior remain required. It cannot write
userdata or settle an uncertain historical effect.

The real-owner host tests exposed a lifecycle defect: stopped or failed
maintenance wrote `maintenanceStopped` as an operation failure code, outside the
Core's closed vocabulary. Such a Job could execute its refusal/failure path but
fail status decoding. The producer now uses the existing
`executionConfirmedNotPerformed` code before dispatch and `executionFailed`
after a known failure. No failure-code enum or accepted requirement is widened.

Read-only Import retention recognizes the exact prior input-compatible Catalog.
It grants no execution authority and leaves old Jobs, Journals and capability
records unchanged. Reversing only the proposed flag reproduces the complete
published Catalog digest; older frozen descriptor tables remain exact.
