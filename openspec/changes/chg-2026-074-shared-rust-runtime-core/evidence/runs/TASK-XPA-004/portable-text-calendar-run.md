Gate inventory group 2 (G03 host text, G04 calendar and legacy date parsing;
`windows-gate-inventory-20260930.md`, PR #2331), with its GJ-1 hop 1 ride-along:
the Bootstrap registry's registration-time check, which refused every timestamp

## 2. Parity evidence

### On macOS (CI, `Rust workspace (xcode-27)`): portable against CoreFoundation itself

- Character sets: every scalar U+0000..U+10FFFF (surrogates excluded), all three sets.
- NFC and NFD of every single scalar; NFC of every table starter followed by every
  composition second and every non-starter; every Hangul L+V and LV+T pair (including
  the out-of-range T); `a` + every ordered pair of non-starters (reordering and blocking).
- Calendar composition: years 0, 1..4, 99..101, 399..401, 1000, 1499..1583, 1600, 1700,
  1800, 1900, 1969..2026, 2100, 2400, 9998, 9999, 10000, 506714 × every month × days
  0, 1, 4, 5, 14, 15, 28..32 × three times, plus every day of October 1582; results
  compared as f64 bits.
- Calendar decomposition: ±40 days around the cutover and around 0001-01-01 (with
  -0.5 and +0.25 fractions), the four-digit-year limits in both eras, ±1e12..±1e16, ±1e300,
  NaN/±∞, the rounding carry, and 22,000 seeded instants in [-3.2e11, 2.6e11] s.
- Day addition: 3,006 seeded and fixed instants × 13 day counts (including -1, 0 and
  `i32::MAX`), compared as f64 bits.
- Legacy formatter: every field value in the written shape (13 years × months 00..13 ×
  days 00..32; hours, minutes, seconds 00..99; offsets ±00..99 with minutes 00, 30,
  59, 60, 99) must answer exactly as Foundation; over that set plus 1,941 other
  spellings (every printable ASCII byte at every position, ICU-only forms), nothing
  the portable check accepts may be refused by Foundation.

A mismatch lists the first 40 inputs with both answers. Result: see §6.

### Local cross-check against an independent ICU (not an oracle)

Windows' system ICU 72.1 (`icu.dll`, `udat_parse` non-lenient, pattern
`yyyy-MM-dd'T'HH:mm:ssXXXXX`, `en_US_POSIX@calendar=iso8601`, GMT) on 15,212 strings:
0 differences inside the written shape, 0 strings accepted here and refused by ICU,
13 single-byte mutations ICU accepts outside the shape (for example `z`, a leading
or inner space). For the 9,392 accepted `Z` dates, `host_gregorian_seconds` equals
ICU's instant exactly, including the Julian years and October 1582. Apple's ICU and
CoreFoundation layer may differ from ICU 72, which is why the macOS test compares
with CoreFoundation itself.

## 3. Decisions to confirm (T1)

1. **Unicode version.** Tables are Unicode 17.0.0. The macOS CI image is macOS 27; the
   brief names macOS 26 as the reference. The exhaustive oracle is exact, so on a Mac
   whose CoreFoundation is Unicode 16 it would fail for the scalars Unicode 17 added
   (by design: it detects drift rather than hiding it). Not verified on macOS 26 here.
2. **Legacy formatter narrowing.** ICU's parser behind `ISO8601DateFormatter` also takes
   spellings the formatter never writes: one-digit or over-long fields, every Unicode
   decimal digit script, leading white space and bidi marks before fields, `z`,
   `GMT`/`UTC`/`UT` zones, basic and seconds offsets, and any trailing text (ICU 72
   even takes `∞`, `NaN` and an `E` exponent as seconds). The portable check refuses
   them on every OS, macOS included, so a registry record holding one fails closed as
   `Header` instead of being read as one ICU version happens to. Every timestamp the
   Swift owner (`ISO8601DateFormatter().string(from:)`) and the Rust owners write is in
   the shape, and within it the answers are equal. This changes macOS behaviour only
   for such hand-made records.
3. `host_canonical_text` now always returns `Some` (the Foundation form returned
   `None` only on allocation failure). `host_gregorian_seconds` refuses a month
   outside 1...12, which no caller passes (Session and FormatStyle parsers validate
   it; Foundation's lenient calendar would have rolled it over).
4. `host_gregorian_add_days` is `at + days × 86,400` in f64. Whether Foundation's day
   addition keeps every fractional instant bit-identical is what the macOS oracle
   checks; not verifiable here.

## 4. Gates removed

- `arkdeck-platform/src/lib.rs`: `host_text`, `host_calendar`, `host_date_formatter`
  and their re-exports are no longer `cfg(target_os = "macos")`.
- `arkdeck-bootstrap/src/registry.rs` `timestamp`: the non-macOS `false` arm (GJ-1 hop 1).

  `domain_leaves.rs` `hilog_component` (`char::is_alphanumeric`), `trace_inspect.rs`
  `control` (`char::is_control`) — the three T1-risk arms the inventory lists, now on
  the pinned tables.
- `arkdeck-hoststore`: `valid_host_text`/`canonical_host_text` (`false`/`Shape` arms),
  `session_time` (`decode_session_timestamp` `Shape` arm), `format_time`
  `format_timestamp_seconds` and its Swift-reference tests (its Artifact and flash
  callers stay macOS-only for their own reasons, hence a `cfg_attr` dead-code allow
  off macOS, as the file already had for `ParsedTimestamp`).

Not changed: `arkdeck-cli/src/machine_contracts.rs:319-323` (the inventory's fourth
arm) is the Finder hidden flag from `host_entry_presentation` (URL resource values),
not a text or calendar primitive; it belongs to the file-presentation port.

(`bootstrap-tools/2`, `activeSelection`, generation 3) and a registered Bundle on
