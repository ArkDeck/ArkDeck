## 2. What CoreFoundation was recorded to do (and the portable code now does)

The first macOS oracle runs (PR #2336, runs 36665264595, 36666514795 and 36668221403)
showed where CoreFoundation parts from Unicode 17.0.0 and from ICU 72. Each is now
reproduced, and the oracle holds it:

- **Character sets.** `alphanumerics` lacks Todhri (U+105C0..U+105F3, Unicode 16) and
  the Tangut ideograph ranges (U+17000..U+187FF, U+18D00..U+18D1E; Tangut components
  U+18800.. are members). `whitespacesAndNewlines` holds U+200B. `controlCharacters`
  is exactly Cc+Cf. Otherwise the sets are Unicode 17.0.0 (Unicode 16 and 17 additions
  such as Garay, Kirat Rai and CJK Extension J are members).
- **NFC.** One leading U+FEFF is dropped (`CFStringCreateWithBytes` reads it as a byte
  order mark; the old primitive's keys had it). A starter that came precomposed with a
  following starter in one input character (Hangul LV, U+0CCA) joins no starter from
  another input character: `U+AC00 U+11A8` and `U+0CCA U+0CD5` stay, while
  `U+1100 U+1161 U+11A8` and `U+0CC6 U+0CC2 U+0CD5` compose and `U+AC01`/`U+0CCB` stay
  whole. Six Unicode 16 starter-second composites (Gurung Khema U+16126..8, Kirat Rai
  U+16D68..A) stay when precomposed and never form from parts. Todhri has no
  decompositions. The portable code tracks each scalar's input character through
  decomposition and reordering for this.
- **Calendar.** Any instant before Julian day 0.0 (noon, 4713-01-01 BC Julian) reads as
  that instant (decomposition keeps the fraction; day addition drops it); `-0.0` reads
  as the second before the reference date. For year 506714 Foundation refuses days
  29..31 of most months; the only caller beyond year 10000 (Artifact FormatStyle
  comparison) composes day 1, which is pinned.
- **Legacy formatter.** Any four-digit year including 0000, months 01..12, days 01..31
  in every month (2026-02-31 is accepted), hours 00..24, minutes and seconds 00..59,
  any two-digit offset fields. (Windows' ICU 72 refuses year 0000, 2026-02-31 and hour
  24, so Apple's ICU differs; the oracle is Foundation itself.)

## 3. Parity evidence

### On macOS (CI): portable against CoreFoundation itself

- Character sets: every scalar U+0000..U+10FFFF (surrogates excluded), all three sets;
  a mismatch prints the differing scalars as ranges.
- NFC and NFD of every single scalar; NFC of every table starter followed by every
  composition second and every non-starter (391,391 pairs); every Hangul L+V and LV+T
  pair; `a` + every ordered pair of non-starters (937,024); 21 probes for the starter
  rule and the byte order mark. A mismatch prints both normalizations.
- Calendar composition: years 0, 1..4, 99..101, 399..401, 1000, 1499..1583, 1600, 1700,
  1800, 1900, 1969..2026, 2100, 2400, 9998..10000 × every month × days 0, 1, 4, 5, 14,
  15, 28..32 × three times; every day of October 1582; year 506714 day 1; f64 bits.
- Calendar decomposition: ±40 days around the cutover and 0001-01-01 (with fractions),
  the four-digit-year limits, ±1e12..±1e16, ±1e300, NaN/±∞, ±0, the rounding carry, and
  22,000 seeded instants in [-3.2e11, 2.6e11] s. Day addition: 3,006 instants × 13 day
  counts (including -1, 0 and `i32::MAX`); f64 bits.
- Legacy formatter: every field value in the written shape (13 years × months 00..13 ×
  days 00..32; hours, minutes, seconds 00..99; hour 24 with other minutes and seconds;
  offsets ±00..99 with minutes 00, 30, 59, 60, 99) answers exactly as Foundation; over
  that set plus 1,941 other spellings, nothing the portable check accepts is refused
  by Foundation.

### Local cross-check against an independent ICU (not an oracle)

Windows' system ICU 72.1 (`udat_parse`, pattern `yyyy-MM-dd'T'HH:mm:ssXXXXX`) on
15,212 strings agreed with the first portable formatter inside the shape and gave the
same instant as `host_gregorian_seconds` for 9,392 dates, including the Julian years.
Apple's formatter turned out more lenient on days, hour 24 and year 0000 (§2), which is
why only the macOS oracle decides.

## 4. Decisions to confirm (T1)

1. **Unicode data version.** The tables are Unicode 17.0.0 with the differences
   CoreFoundation showed on the CI image (macOS 27). The brief names macOS 26 as the
   reference; it was not available here. The oracle is exact, so a Mac whose
   CoreFoundation differs would fail the test and show the scalars (drift is
   detected, not hidden).
2. **Legacy formatter narrowing.** ICU's parser behind `ISO8601DateFormatter` also takes
   spellings the formatter never writes: one-digit or over-long fields, other decimal
   digit scripts, leading white space and bidi marks, `z`, `GMT`/`UTC`/`UT` zones, basic
   and seconds offsets, trailing text. The portable check refuses them on every OS,
   macOS included, so a registry record holding one fails closed as `Header` instead of
   being read as one ICU version happens to. Every timestamp the Swift owner
   (`ISO8601DateFormatter().string(from:)`) and the Rust owners write is in the shape,
   and inside it the answers are equal. This changes macOS behaviour only for such
   hand-made records.
3. **Byte-order-mark key.** `host_canonical_text` keeps the old primitive's dropping of
   one leading U+FEFF, which Swift's `String` equality does not do. Kept for byte
   identity with the macOS keys; say if it should instead follow Swift.
4. `host_canonical_text` always returns `Some`; `host_gregorian_seconds` refuses a
   month outside 1...12, which no caller passes.
