# TASK-XPA-011 — Windows workspace provider (WM3 GJ-5, PR 2), 2026-10-04

- Task: TASK-XPA-011, WM3 slice GJ-5, second PR: the workspace provider on Windows. The
  daemon composes `WorkspaceComposition` over the registered projects. The planner, admitter,
  runner and reconciler serve the workspace lane, and `workspace.inspect-source@1` runs end to
  end through the inspector the host configured. Every profile-served workspace operation
  stays unavailable, gated on one undecided identity rule: which code-owned source tools a
  Windows Runtime may trust (see "Gate").
- Base: one commit on `origin/main` `9f26fc0a` (#2450, PR 1, the analyzer provider).
- Host: the Windows 11 x64 reference host (Windows 11 Pro 10.0.26200), non-elevated. Nothing
  was installed, elevated or reconfigured. No board, `hdc`, DevEco, JDK, keystore, credential
  or git was used. Every daemon ran over a private development root with every other
  `ARKDECK_`/`OHOS_HDC_` input removed.

## Gate

On macOS a registered OpenHarmony project resolves to a profile that pins Swift's fixed
system tools. Windows ships none of them, and no rule says which `grep`/`sed`/`patch`/`tar`/
`git` a Windows Runtime may trust. Candidates include `System32\tar.exe`, Git for Windows or a
registered toolchain. GJ-5's rule is "toolchain identity from registered references, never
from PATH", so this is an identity decision for the maintainer, not an implementation detail.
Until it is decided, every profile-served operation is unavailable with the reason above, and
its plan is refused before admission with zero dispatch:

- `workspace.read-source-range@1`, `inspect-git-status@1`, `inspect-diff@1`
- `prepare-isolated-copy@1`, `apply-patch@1`, `revert-patch@1`, `sweep-isolated-copies@1`
- `build-openharmony@1`, `run-tests@1`, `create-checkpoint@1`, `symbolize-crash@1`
- `sign-openharmony-hap@1`

The test proves this refusal. The lane code behind the gate is built on Windows and is
exercised as soon as a profile resolves.

## Delegated minor decisions, pending the next rulings batch

1. **Windows workspace paths.** An absolute path is the host's standard `X:\…` spelling.
   This is the spelling the project registration pins and the platform's verified handles
   require. A path relative to a project root keeps Swift's `/`. A colon is refused in a
   relative path or glob (drive or alternate data stream).
2. **Hidden entries.** An entry is hidden when its name starts with `.` or it has the hidden
   attribute. No directory is a package.
3. **Links in an isolated copy.** A link or junction inside the source tree is refused as an
   unsafe entry, not recreated. Windows link creation needs a privilege, and a junction is not
   a POSIX link.
4. **A file's unchanged test during a copy.** On NTFS, a file is unchanged when its length,
   attributes, creation time and last-write time are all unchanged. This stands in for the
   POSIX dev/ino/mode/mtime/ctime check.
5. **`argument_zero`** (SwiftPM's multi-call role) is refused on Windows before anything runs.
6. **The census** names `workspaceOperations` at its macOS position.
