# Rust dependency checks

Run from `rust/` so rustup uses the committed toolchain:

```sh
cargo install --locked --version 0.20.2 cargo-deny
cargo install --locked --version 0.10.2 cargo-vet
cargo fetch --locked
cargo deny --locked check
cargo vet --locked --no-registry-suggestions
```

`deny.toml` restricts the complete dependency graph to explicit crate versions,
crates.io sources and the listed licenses. Advisory and audit failures stop the
local and hosted gates. Native CI covers Windows, macOS and Linux; it does not
establish Windows device acceptance.

`config.toml` imports the public audit sets from
[Google](https://github.com/google/supply-chain),
[Mozilla](https://github.com/mozilla/supply-chain),
[Bytecode Alliance](https://github.com/bytecodealliance/wasmtime/tree/main/supply-chain),
[ISRG](https://github.com/divviup/libprio-rs/tree/main/supply-chain) and
[Zcash](https://github.com/zcash/rust-ecosystem/tree/main/supply-chain), using the
URLs published in the [cargo-vet registry](https://github.com/mozilla/cargo-vet/blob/main/registry.toml).
`imports.lock` is generated by cargo-vet and records the imported assertions and
registry publisher metadata consumed by CI.

The locked `zmij 1.0.21` uses a complete imported source-audit chain: [Mozilla full audit of 1.0.20 and delta to 1.0.21](https://github.com/mozilla/supply-chain/blob/0541e4d34ad95189c2d628461183d818ba1d38eb/audits.toml#L11299).
This compatible pin replaces 1.0.23 and uses the imported source audits without
requiring publisher trust or an exemption for `zmij`.

Each `trusted` entry begins on that publication day and ends the following day.
Cargo-vet compares publication dates using `[start, end)`, so the entry covers
one UTC day and authorizes no future publishing period. These are publication
windows, not expiration dates for the already locked release. The exact version
allowlist and `Cargo.lock` checksum restrict acceptance further: another version,
even from the same publisher on the same day, cannot pass the combined gate
without a reviewed allowlist and lock change. No trust applies to every crate
from a publisher, and no renewal is automatic.

Publisher trust does not establish that a release has no vulnerability or that
its source has been reviewed. A compromised publishing account or defective
release can satisfy the publisher check. RustSec advisories, contract vectors,
failure-path tests and platform identity checks provide separate checks; they
do not replace source audits or real Windows device acceptance.

For a deliberate audit refresh, run `cargo vet regenerate imports` locally and
review the resulting `imports.lock` diff together with the dependency change.
Do not run `cargo vet init`, add exemptions, regenerate exemptions, or widen a
publisher window merely to make the check green. Dependency additions, version
changes and trust-policy changes are explicit PR review items. CI only consumes
the committed lock and policy.
